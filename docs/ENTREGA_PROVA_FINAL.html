Demonstra a hierarquia de atores, as inclusões obrigatórias («include») para cronometragem e exercícios, e as extensões condicionais («extend») para cálculo de recorde pessoal (PR) e interações sociais.

Destaques do Caso de Uso:
  • Herança de Atores: O Atleta herda os privilégios do Visitante e ganha acesso ao token de autorização JWT.
  • Relação «include»: A execução de um treino exige obrigatoriamente o controle de cronômetro de descanso entre séries.
  • Relação «extend»: Bater um Recorde Pessoal (PR) é uma extensão disparada somente se a carga superou o histórico.

4.3. Modelo Entidade-Relacionamento (MER / DER)

O MER especifica o esquema relacional físico implementado no PostgreSQL 18 com chaves primárias UUID, restrições de unicidade (UNIQUE), chaves estrangeiras e integridade referencial com exclusão em cascata (CASCADE).

MER / DER — Modelo Entidade-Relacionamento Relacional
Mapeamento rigoroso de todas as 8 tabelas do banco de dados relacional com tipagem estrita, cardinalidades e constraints.
erDiagram
    USERS ||--o{ WORKOUTS : "1:N (possui)"
    USERS ||--o{ FOLLOWS : "1:N (seguidor)"
    USERS ||--o{ FOLLOWS : "1:N (seguido)"
    USERS ||--o{ SESSION_LIKES : "1:N (curte)"
    USERS ||--o{ SESSION_COMMENTS : "1:N (comenta)"

    WORKOUTS ||--o{ EXERCISES : "1:N (composto por [CASCADE])"
    WORKOUTS ||--o{ WORKOUT_SESSIONS : "1:N (execuções [CASCADE])"

    WORKOUT_SESSIONS ||--o{ SESSION_LOGS : "1:N (contém [CASCADE])"
    EXERCISES ||--o{ SESSION_LOGS : "1:N (referencia)"
    WORKOUT_SESSIONS ||--o{ SESSION_LIKES : "1:N (recebe [CASCADE])"
    WORKOUT_SESSIONS ||--o{ SESSION_COMMENTS : "1:N (recebe [CASCADE])"

    USERS {
        uuid id PK
        varchar name "NOT NULL"
        varchar email "UK NOT NULL"
        varchar password "NOT NULL"
        varchar avatarUrl "NULL"
        integer xp "DEFAULT 0 NOT NULL"
        timestamp createdAt "DEFAULT NOW()"
        timestamp updatedAt "DEFAULT NOW()"
    }

    WORKOUTS {
        uuid id PK
        uuid userId FK "NOT NULL"
        varchar name "NOT NULL"
        varchar goal "NOT NULL (Enum)"
        varchar level "NOT NULL (Enum)"
        timestamp createdAt "DEFAULT NOW()"
        timestamp updatedAt "DEFAULT NOW()"
    }

    EXERCISES {
        uuid id PK
        uuid workoutId FK "NOT NULL"
        varchar name "NOT NULL"
        varchar modality "NOT NULL (Enum)"
        integer sets "NOT NULL"
        integer repetitions "NOT NULL"
        float weight "DEFAULT 0"
        integer restTime "DEFAULT 60"
        text notes "NULL"
        integer order "NOT NULL"
        timestamp createdAt "DEFAULT NOW()"
        timestamp updatedAt "DEFAULT NOW()"
    }

    WORKOUT_SESSIONS {
        uuid id PK
        uuid workoutId FK "NOT NULL"
        timestamp startedAt "NOT NULL"
        timestamp endedAt "NULL"
        integer durationSeconds "DEFAULT 0"
        float totalVolume "DEFAULT 0"
        text notes "NULL"
        timestamp createdAt "DEFAULT NOW()"
        timestamp updatedAt "DEFAULT NOW()"
    }

    SESSION_LOGS {
        uuid id PK
        uuid sessionId FK "NOT NULL"
        uuid exerciseId FK "NOT NULL"
        integer setNumber "NOT NULL"
        float weight "NOT NULL"
        integer repetitions "NOT NULL"
        boolean isCompleted "DEFAULT FALSE"
        boolean isPersonalRecord "DEFAULT FALSE"
        timestamp createdAt "DEFAULT NOW()"
    }

    FOLLOWS {
        uuid id PK
        uuid followerId FK "NOT NULL"
        uuid followingId FK "NOT NULL"
        timestamp createdAt "DEFAULT NOW()"
    }

    SESSION_LIKES {
        uuid id PK
        uuid sessionId FK "NOT NULL"
        uuid userId FK "NOT NULL"
        timestamp createdAt "DEFAULT NOW()"
    }

    SESSION_COMMENTS {
        uuid id PK
        uuid sessionId FK "NOT NULL"
        uuid userId FK "NOT NULL"
        text content "NOT NULL"
        timestamp createdAt "DEFAULT NOW()"
    }
Regras de Integridade Relacional do Banco de Dados:
  • Índices Únicos (UK): Impede e-mails duplicados em USERS, likes duplicados na mesma sessão ([sessionId, userId]) e duplicações de seguidores ([followerId, followingId]).
  • Deleção em Cascata (ON DELETE CASCADE): Ao remover um treino, seus exercícios e sessões associadas são excluídos atomicamente, garantindo consistência relacional sem registros órfãos.
